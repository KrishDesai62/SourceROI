## Package security

The previous handoff left trusted digest verification/manual extraction to the operator. The existing source packager also needed stronger member checks. New standalone tools/verify_pilot_archive.py checks a caller-supplied trusted archive SHA-256 **before parsing or writing**, then bounds compressed bytes, gzip-expanded bytes including metadata, member counts and file sizes. It rejects noncanonical/absolute/traversal/backslash paths, symlinks, hardlinks, special files, privileged modes, duplicate paths, file/directory collisions, unexpected files or empty directories and checksum mismatches. It extracts only verified regular files into an exclusively created private destination; existing destinations are refused. The same opened archive handle is used after digest verification. A trusted verifier/digest must be obtained before archive code runs; an archive’s own hash file is not an authenticity root.

The source bundle builder now requires the trusted locally built sdist SHA before extraction and rejects nonregular/duplicate/oversized members. The pilot extractor does not rely on permissive extractall behavior. Same-account filesystem attacks, archive/parser process isolation and independently reviewed supply-chain authenticity remain PENDING; this is not a security certification. Verify a fresh archive before executing code or creating bytecode/state in a working extraction.

Adversarial tests include traversal, absolute/backslash paths, symlink/hardlink/device, duplicates, added files/empty directories, resource bounds, existing outputs and digest-first ordering. The earlier sealed package also passes the new strict extractor without modification. New bundle/verifier SHA-256 values and exact test counts are in docs/artifacts/design-partner/summary.json and TRUSTED_ARTIFACTS.json. Do not overwrite the earlier package or its manifest.
