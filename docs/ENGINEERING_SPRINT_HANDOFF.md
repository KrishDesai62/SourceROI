## Enable optional passage selection

In a new workspace/configuration, explicitly set:

```json
{
  "chunk_strategy": "sentences",
  "max_chunks": 3,
  "retrieval_policy": {"name": "passage_coverage", "k": 3}
}
```

These are `settings` fields. Existing defaults and saved historical workspaces remain fixed-chunk retrieval. Create and review a new configuration/version before comparing runs. A changed strategy is not a controlled data-only update. The index emits exact extracted-source offsets and content-bound chunk IDs. It is a lexical heuristic, not semantic fact extraction. Sentence boundaries, abbreviations, embedded historical facts and unusual qualifications still require review. Retained conflicting predicates may exceed target k; an insufficient character budget then yields empty context instead of hiding one side.

## Review-only numeric diagnosis

Use `python -m sourceroi --project WORKSPACE diagnose --run-id RUN_ID --output findings.json --calculation-spec calculation.json`. The optional specification maps failed task IDs to declarations without values:

```json
{
  "allowance_difference": {
    "operation": "subtract",
    "operands": [
      {"subject": "overseas allowance", "unit": "units", "period": "Q2"},
      {"subject": "overseas allowance", "unit": "units", "period": "Q1"}
    ]
  }
}
```

Supported source grammar is narrowly `NUMBER UNIT for PERIOD` within a literal indexed sentence containing the subject. Lookup, addition and subtraction use decimal arithmetic. Missing/ambiguous operands, unknown requested applicability, selected negation/qualification patterns and unit conversion produce no candidate or an input error. Source quotes, original-document offsets, passage hashes and both operands are retained. This is a **REVIEW proposal**, not an agent answer, semantic adjudication or automatic repair. No rate/value is hardcoded. More complex prose is unsupported; reviewers must decide whether the declared subject, period and formula fit the actual question.
