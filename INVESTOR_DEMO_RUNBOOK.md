# Three-to-five minute technical demonstration

This demonstration replays immutable **synthetic authored** evidence. It makes no model calls, deploys nothing and supplies no customer or independent approval. Run from the existing SourceROI checkout; no new dependencies required for the replay.

```bash
python tools/investor_demo.py
```

The command verifies four historical artifact hashes before showing results. Do not edit the evidence to change a verdict. It is a read-only replay, not live inference.

1. **0:00–0:40:** Open docs/artifacts/native-tables/table-release.json. Show the registered `fixture::report.csv`, its baseline/candidate hashes and the literal `12` → `14` source update in `specification.changes`. This is synthetic source-owner intent.
2. **0:40–1:20:** Expand the specification impact and evaluation proposals. Show protected expectations and the recorded fixture review. Explicitly state that the named fixture decisions do not represent a real independent person.
3. **1:20–2:00:** Open table-data-ci.json. This separate bad candidate contains `15`, disagrees with expected `14`, and is blocked. The replay displays a recorded evaluation; it does not rerun a model or claim a previously unobserved regression.
4. **2:00–2:40:** Inspect task diagnosis, citations, numeric binding and cell/header quotes in table-release.json. Explain that source attribution and literal arithmetic checks differ from independent semantic correctness.
5. **2:40–3:20:** Open table-isolated-repair.json. The repair changes the isolated copy to `14`; the original bad candidate stays `15`. Before BLOCK, after REVIEW, overall INCONCLUSIVE: semantic review still missing.
6. **3:20–4:00:** Show INVESTOR_EVIDENCE.md. Passage selection used fewer captured tokens historically, but Qwen quality failed and global native usage was incomplete. No quality-preserving or monetary savings claim. Maintained conventional evaluation tied detection.
7. **4:00–4:30:** Show final verdict REVIEW, strict policy missing semantic review, source/config/task versions and exports. Show PILOT_ONBOARDING.md as the next real developer workflow.
